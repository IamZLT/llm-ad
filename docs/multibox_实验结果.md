# 多框 Outcome 实验结果（截至 2026-09-13）

> 记录当前 **SFT + GRPO** 的实测数字，方便对照后续改动。
> 评测口径一律是：VisA 训练 → **MVTec test 分层 200 张**（异常 105 / 正常 95，15 类 × 约 13–14 张）。

旧单框 GRPO（5002 端口、`ckpt-2650`）见 [5002模型_MVTec评测分析.md](5002模型_MVTec评测分析.md)，口径不同，不能逐行比大小。

另外有一次 2B 冒烟：`train_20260913_041952_546651`，只跑到 a=100，数字与全量 run 的 a=100 几乎一致，下文不单独展开。

**2B 新奖励（`score_output`）**：

```
异常正确: task = iou*mask_iou + count*count_r + dense*set_loc
                 + cand*cand_coverage + refine*clip(delta, ±refine_clip)
正常正确: task = 1.0 + focus_weight * focus_reward(N_cand, max=3)
```

`cand_coverage` 用 `candidate_hits_comp`：IoU≥0.1 **或** 候选中心落在 GT 框内即算命中（适配 H 的 patch 对齐小框）。巨框（面积比 > `cand_max_area_frac=0.1`）不计入覆盖，防 hack。

## 2. 一句话结论

- **机制已经活了**：2B 上 Problem 3（refine 退化）和 Problem 4（focus 死掉）都被纠正。eval 上异常样本 `candidate == final` 为 **0%**（4B 是 92%）；正常样本空候选为 **0%**（4B 是 81%），localize-then-reject 约 **82–90%**。
- **分类优于 4B 对照**：好的 2B checkpoint 平衡准确率 **0.89**、FPR **0.10–0.15**；4B 最好是 0.87 / 0.19。
- **定位仍明显落后 4B**：2B 最好 mask mIoU **0.362**（a=1100），4B 最好 **0.495**（a=200）。F1@50 同理：0.30 vs 0.49。
- **训练曲线还在涨**：VisA rollout 上异常 mask IoU 从 0.30 升到最近窗口 **0.45**，`cand_coverage` 从 0.41 升到 **0.68**。MVTec eval 的 mIoU 在 0.32–0.36 震荡，没有同步涨上去。
- **H 先验上限**：同一套 2B eval 上，H best-k 框的 mask IoU 是 **0.382**，component recall@0.1 是 **0.786**。模型 mIoU 已经贴近 H 的 IoU 天花板，再靠 LoRA 把框收紧的空间有限。

| 项 | 2B（新语义） | 4B（旧语义） |
|---|---|---|
| 输出目录 | `outputs/train/region_sft_multibox_2b/` | `outputs/train/region_sft_multibox_4b/` |

| `ground` | `candidate_bboxes_2d = H 候选` | 异常抄 GT 框，正常写 `[]` |
| `verify` | 按覆盖规则写 discover / refine / keep / reject | 异常几乎全是 keep，正常走空候选 |

SFT 没有单独跑 MVTec 数字；冷启动效果看 RL 的 **a=100**（几乎就是 SFT 策略 + 少量 GRPO）。

2B a=100 已经出现完整五段、非空候选、`delta_refine≈0.09`、`focus≈0.45`，说明新 SFT 文本把行为教出来了。此时异常侧 verify 仍以 **discover** 为主（88/105），随后 RL 把它压成 **refine**。

## 9. 现在能确定的、和还不能确定的

已经确定：

1. 新 SFT 语义 + 双边 refine / cand 覆盖 / focus 带宽，**不必改五段流程**就能让 ground/verify 真正干活。
2. 2B 分类已经可用，且比同协议 4B 更稳（更低 FPR）。
3. 2B 定位的瓶颈不像是「奖励没激活」，更像是 **448 全局图上看不见小缺陷 + LoRA 改不了视觉分辨率**。训练域 IoU 在涨、测试域贴着 H IoU 天花板，符合这一点。
4. 零优势组偏多，后半段 FPR 抖动，和「正常样本组内奖励太齐」一致。

还不能当最终数：

- 2B 两个 epoch 没跑完；a=1700 不是最终 test。
- 2B vs 4B 同时差了容量、SFT 语义、奖励、GT 合并，不能把 0.36 vs 0.50 全部归因于模型大小。
- 没有 H 消融（`prior.condition: none / shuffled`），还不能量化 region token 的因果贡献。
- 没有完整 MVTec test（`final_eval_num_samples=null` 尚未跑）。
